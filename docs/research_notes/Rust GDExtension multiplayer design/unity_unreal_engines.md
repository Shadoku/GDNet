# Multiplayer / netcode libraries in Unity, Unreal and other engines: programming models and developer experience (state as of Nov 2026)

Scope note: Bevy and Godot are covered by other researchers. Dates: anything not explicitly dated below was read from the current ("latest"/"current") docs pages in Nov 2026; facts marked **(older)** come from dated 2023–2025 material. GitHub star counts are as shown on the repo pages on 2026-11-08 unless noted.

## Key question 1: Unity libraries (NGO, Netcode for Entities, Mirror, FishNet, PurrNet, Photon PUN2/Fusion/Quantum, Normcore, coherence, SpatialOS)

### Takeaway
Unity has converged on three API dialects: (a) attribute-on-member + IL post-processing (NGO `[Rpc]`, Mirror `[SyncVar]`/`[Command]`, Fusion `[Networked]`/`[Rpc]`, coherence `[Sync]`/`[Command]`), (b) generic wrapper fields (NGO `NetworkVariable<T>`, FishNet `SyncVar<T>`, PurrNet `SyncVar<T>`), and (c) data-oriented/declarative (Netcode for Entities `[GhostField]` on ECS structs, Quantum's `.qtn` DSL, Normcore's `[RealtimeModel]` partial-class model compilation). Tick-based input→prediction→reconcile loops (FishNet `[Replicate]`/`[Reconcile]`, Fusion `FixedUpdateNetwork`+`GetInput`, N4E `PredictedSimulationSystemGroup`, Quantum full determinism) are now the differentiator; Mirror and NGO still treat prediction as experimental or absent. Ownership is drifting from pure server authority toward "distributed/shared authority" modes (NGO DA, Fusion Shared, coherence, Normcore, Roblox) for co-op/social games.

### Cited Findings

#### Unity Netcode for GameObjects (NGO, com.unity.netcode.gameobjects 2.x)
- Repo: 2.3k stars, 464 forks; README: "a Unity package that provides networking capabilities to GameObject & MonoBehaviour workflows", works with many low-level transports incl. Unity Transport — [GitHub](https://github.com/Unity-Technologies/com.unity.netcode.gameobjects)
- **State marking**: `NetworkVariable<T>(T value = default, NetworkVariableReadPermission readPerm = Everyone, NetworkVariableWritePermission writePerm = Server)`; permission enums `Read: Everyone|Owner`, `Write: Server|Owner`; defaults in client-server: server read/write, clients read-only; `OnValueChanged(previous, current)` subscribed in `OnNetworkSpawn`; `NetworkList<T>` must be initialised in `Awake` (declaration-time init "can cause memory leak errors"), `OnListChanged` passes `NetworkListEvent<T>`, add items only on the server; custom types implement `INetworkSerializable` with `NetworkSerialize<T>(BufferSerializer<T> serializer) where T : IReaderWriter` branching on `serializer.IsReader`; collection changes require `NetworkVariable<T>.CheckDirtyState()` (recursive, "can be costly"); strings unsupported as managed types (use `FixedString`); custom types need compile-time serializer generation via `GenerateSerializationForType`/`GenerateSerializationForGenericParameter`, and codegen "only inspects fields inside NetworkBehaviour types" — [NGO 2.4 NetworkVariable docs](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.4/manual/basics/networkvariable.html)
- **RPC shape** (unified `[Rpc]`, NGO 2.x): method name must end in `Rpc`; call site is rewritten by an ILPostProcessor pass; `RpcParams` as last parameter carries `Receive.SenderClientId` and runtime targets (`RpcTarget.Single(id, RpcTargetUse.Temp)`); attribute params `RequireOwnership` (default false; throws when a non-owner invokes), `Delivery = RpcDelivery.Reliable|Unreliable`, `AllowTargetOverride`; `SendTo` options: `Server, NotServer, Owner, NotOwner, Me, NotMe, Everyone, ClientsAndHost, SpecifiedInParams` — [NGO 2.4 RPC docs](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.4/manual/advanced-topics/message-system/rpc.html)
  ```csharp
  [Rpc(SendTo.Server)]
  public void PingRpc(int pingCount, RpcParams rpcParams)
  {
      PongRpc(pingCount, "PONG!", RpcTarget.Single(rpcParams.Receive.SenderClientId, RpcTargetUse.Temp));
  }
  [Rpc(SendTo.SpecifiedInParams)]
  void PongRpc(int pingCount, string message, RpcParams rpcParams) { }
  ```
  (verbatim from the same page). Legacy `[ServerRpc]`/`[ClientRpc]` are not described on the current page (see Gaps).
- **Distributed Authority (DA)**: "authority is spread across clients"; the first client to join is the *session owner* and manages global state; if it disconnects another client is promoted automatically; DA "avoids the added latency of a listen server"; service is provided through the Multiplayer Services package with "a free tier for bandwidth and connectivity hours"; stated limits: no single physics simulation, "clients are trusted more, so cheating can be easier", "typically not suited to high-performance competitive games that need an accurate predictive motion model" — [NGO 2.4 DA concepts](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.4/manual/terms-concepts/distributed-authority.html)
- DA ownership permission flags (`NetworkObject.OwnershipStatus`, DA only): `Distributable` (redistributed on join/leave), `Transferable` (immediate transfer if unlocked), `RequestRequired` (must be requested, locked after transfer), `SessionOwner` (always owned by the session owner, moves with it), `None` (static, e.g. player objects); `NetworkObject.SetOwnershipLock`; settings appear in the editor only with the Multiplayer Services SDK installed and "have no effect in client-server topology"; `HasAuthority` works in both topologies (recommended), `IsServer` is client-server only; in DA NetworkVariables are "automatically set to owner-write and everyone-read" — [NGO 2.4 ownership docs](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.4/manual/basics/ownership.html)
- **Complaints** (Unity Discussions thread, 2024–25): performance "awful ... unless you build much from scratch", "unintuitive implementation details, confusing console warnings and errors, weak tooling"; `NetworkTransform`/`NetworkAnimator` "terribly inefficient" — NetworkAnimator syncs the whole Animator state machine so it "can't handle 100+ networked animated characters"; praise: docs "more complete, with code examples", easier to pick up given tutorials and Unity backing — [Unity Discussions: Fishnet vs NGO](https://discussions.unity.com/t/fishnet-vs-netcode-for-game-objects/928418)
- One roundup frames NGO as "a good fit for rapid prototyping and small-scale games"; Edgegap's comparison says NGO is the beginner option "but with well documented hard limitations" — [appwill 2025](https://appwill.co/multiplayer-in-unity-best-networking-solutions-2025/); [Edgegap](https://edgegap.com/blog/easiest-unity-netcode-for-game-developers)

#### Unity Netcode for Entities (N4E, com.unity.netcode 1.6)
- **Marking state**: `[GhostComponent]` on a component struct declares prefab-type/child/receive scope but "won't make your component fields replicate"; `[GhostField]` on a field/property selects it, and "once a component has at least one field marked with `[GhostField]`, it becomes replicated"; `[GhostEnabledBit]` replicates the enabled bit of an `IEnableableComponent`; components must be on the prefab at authoring time — [N4E ghost snapshots](https://docs.unity3d.com/Packages/com.unity.netcode@1.6/manual/ghost-snapshots.html)
- `[GhostField]` options: `Quantization` (float × int, disabled by default), `Composite` (one change bit for the whole struct for delta compression), `SendData` (false excludes), `Smoothing = Clamp|Interpolate|InterpolateAndExtrapolate` (for Interpolated ghosts), `MaxSmoothingDistance` (teleport cut-off), `SubType` (custom serializer via `GhostFieldSubType`); only public members of `IComponentData` serialize; `IInputComponentData` fields can be annotated to replicate inputs server→client "which can support client-side prediction of other players" — [N4E GhostField](https://docs.unity3d.com/Packages/com.unity.netcode@1.6/manual/ghostfield-synchronize.html). Illustrative shape (from that page):
  ```csharp
  public struct PlayerState : IComponentData {
      [GhostField] public int Health;
      [GhostField(Quantization = 1000, Smoothing = SmoothingAction.Interpolate)] public float2 Position;
      public float2 LocalOnly; // not replicated
  }
  ```
- Ghost modes: Supported = All/Interpolated/Predicted; Default = Interpolated/Predicted/Owner predicted (owner predicts, others interpolate; needs `GhostOwner` with `NetworkId`); Optimization `Dynamic` vs `Static` (not sent when unchanged); `Importance` decides which chunks go in a bandwidth-limited snapshot (per chunk, not per entity); `MaxSendRate` in Hz "not always enforced"; server sends one snapshot per connection per network tick; if `NetworkTickRate` < `SimulationTickRate` connections are served round-robin — [N4E ghost snapshots](https://docs.unity3d.com/Packages/com.unity.netcode@1.6/manual/ghost-snapshots.html)
- **Prediction loop**: `PredictedSimulationSystemGroup` runs fixed-step on client and server and "can run multiple times per frame"; on a new snapshot the client restarts from "the oldest tick applied to any entity" and resimulates to the target tick — on a 300 ms connection "expect about 22 resimulated ticks in one frame"; partial snapshots mean systems must filter on the `Simulate` enableable tag (legacy `PredictedGhost.ShouldPredict(tick)` not recommended); `NetworkTime.IsPartialTick`, `NetworkTime.IsFirstTimeFullyPredictingTick` guards one-shot effects; `IInputComponentData` is auto-fetched per tick vs legacy `ICommandData` buffers read with `GetDataAtTick` — [N4E prediction](https://docs.unity3d.com/Packages/com.unity.netcode@1.6/manual/prediction-n4e.html); `GhostPredictionSmoothingSystem` reconciles errors over time; prediction can be switched per ghost (e.g. radius) — [N4E prediction index](https://docs.unity3d.com/Packages/com.unity.netcode@1.6/manual/prediction.html)
- **Physics & lag compensation**: interpolated ghosts have physics only on the server (clients make them kinematic); predicted ghosts move `PhysicsSystemGroup` into `PredictedFixedStepSimulationGroup`; lag compensation enabled by `EnableLagCompensation` in `NetCodePhysicsConfig`, server queries `PhysicsWorldHistorySingleton` for the collision world a client saw at a tick; default quantization of transform/velocity is 1000; step batching knobs (`MaxSimulationStepBatchSize`, `MaxPredictionStepBatchSizeFirstTimeTick`) with the note "batching increases the chance of misprediction" — [N4E physics](https://docs.unity3d.com/Packages/com.unity.netcode@1.6/manual/physics.html)
- **Relevancy/interest**: `GhostRelevancyMode` = Disabled | SetIsRelevant | SetIsIrrelevant with a `GhostRelevancySet` of (connection, ghost) pairs; irrelevant ghosts are destroyed on the client; distance importance via `GhostDistanceImportance.Scale` + `GhostDistancePartitioningSystem` spatial tiles; per-chunk `PrioChunk.isRelevant` fast path; `NetworkStreamSnapshotTargetSize` per-connection soft byte limit; `UseSingleBaseline`; snapshot history size symbols `NETCODE_SNAPSHOT_HISTORY_SIZE_16/_6` — [N4E optimizations](https://docs.unity3d.com/Packages/com.unity.netcode@1.6/manual/optimizations.html)

#### Mirror
- Mirror is "free, OSI-certified open source", singleton design ("one networking core per executable"), has "Area of Interest" and lag compensation, "no formal LTS; API changes can require code updates", 10-year history; shipped games cited: *Population: ONE*, *Zoomba*, *Unleashed*; the article's conclusion: Mirror is "likely the strongest and easiest starting point for most Unity multiplayer games" (data partly from a community spreadsheet last reviewed April 2025) — [Edgegap: Easiest Unity Netcode](https://edgegap.com/blog/easiest-unity-netcode-for-game-developers)
- **State marking**: `[SyncVar] public int health = 100;` on a `NetworkBehaviour`; server→client only; new state sent on spawn/late join; applied before `OnStartClient()`; up to 64 SyncVars per script (SyncLists count); "changing a value in the inspector will not trigger an update"; hook attribute names a method called on the client when the value changes — [Mirror SyncVars](https://mirror-networking.gitbook.io/docs/manual/guides/synchronization/syncvars)
- **RPC shape**: `[Command] void CmdName(...)` runs on server (only from your own player object by default; `[Command(requiresAuthority = false)]` with an optional `NetworkConnectionToClient sender = null` filled by Mirror); `[ClientRpc] void RpcName(...)` runs on observers, `includeOwner = false` option; `[TargetRpc] void TargetName(NetworkConnectionToClient target, ...)` (first `NetworkConnection` param selects the receiver, else owner); Cmd/Rpc/Target prefixes; none may be static; arguments limited to Mirror-supported types — [Mirror remote actions](https://mirror-networking.gitbook.io/docs/manual/guides/communications/remote-actions)
- **Interest management**: a single global component on the NetworkManager, built-ins: Spatial Hashing, Hex Spatial Hashing, Distance, Scene, Scene Distance, Match, Team (also owner-only), Custom template, Legacy (deprecated) — [Mirror interest management](https://mirror-networking.gitbook.io/docs/manual/interest-management)
- **Prediction** is "experimental" and the docs advise against production use; `PredictedRigidbody` keeps a transparent predicted physics object, the rendered object following with smoothing, and a debug "remote state" ghost; history saved every ~50 ms and corrections re-apply later deltas; Smooth vs Fast mode; supports Rigidbody-driven actions via a `[Command]` that applies the same force on the server; CharacterControllers not supported out of the box; "predicted player movement is untested"; Mirror "does not use `Physics.Simulate()`" and resimulates individual rigidbodies manually ("trades accuracy for performance"); `OnCollisionEnter`/`OnTriggerEnter` may not fire while predicting; stacked objects "don't yet come to rest properly" — [Mirror client-side prediction](https://mirror-networking.gitbook.io/docs/manual/general/client-side-prediction)
- **(older, 2023)** `NetworkTransform` renamed `NetworkTransformUnreliable` and Reliable/Unreliable `NetworkRigidbody` variants; a teleport fix because "NT Reliable deltas could get out of sync" — [Mirror 2023 changelog](https://mirror-networking.gitbook.io/docs/manual/general/changelog/2023-change-log)
- FishNet's own (vendor) benchmark: FishNet retained 92.6% server performance at 200 CCU vs Mirror 16.8%; an independent academic comparison found bandwidth order Fusion < FishNet < Mirror < NGO and RTTs 46–52 ms across all four — [Fish-Networking vs Mirror](https://fish-networking.gitbook.io/docs/overview/readme/features/performance/fish-networking-vs-mirror); [ResearchGate: Comparison of Open-Source Networking Libraries for Unity](https://www.researchgate.net/publication/382960914_Comparison_of_Open-Source_Networking_Libraries_for_Unity_Engine_in_Higher_Education)

#### FishNet (Fish-Networking, v4)
- Repo: 2.1k stars, 242 forks, "FishNet V4" solution files; "A feature-rich Unity networking solution aimed towards reliability, ease of use, efficiency, and flexibility" — [GitHub](https://github.com/FirstGearGames/FishNet)
- Positioning: "server authoritative by design", "There are no CCU caps or CCU paywalls in FishNet", any host incl. player hosting, transport system, "No breaking API or behavior changes between major versions", major releases no more than every six months, `R` versions toggle Release/Development features — [FishNet overview](https://fish-networking.gitbook.io/docs)
- Instanced design ("one executable can run multiple server instances or connect to several"), "client-side prediction for transforms and rigidbodies", lag compensation is a paid (Pro) feature, formal LTS/API-stability guarantee; shipped games cited: *Arcadius*, *Cat Warfare*, *Skygard Arena* — [Edgegap](https://edgegap.com/blog/easiest-unity-netcode-for-game-developers)
- Pro gates raycast lag compensation ("Fish-Networking Pro is required"), Yak offline transport, NetworkAnimator parameter selection; "extremely flexible sharing license for Fish-Networking Pro" for teams/classrooms; business support tiers grant a lifetime Pro licence; a third-party site lists Pro at $50 once (secondary) — [FishNet Pro page](https://fish-networking.gitbook.io/docs/overview/readme/pro-projects-and-support); [FishNet lag compensation](https://fish-networking.gitbook.io/docs/guides/features/lag-compensation); [Asset Store FishNet Pro](https://assetstore.unity.com/packages/tools/network/fishnet-pro-networking-evolved-287711)
- **State marking (v4)**: `private readonly SyncVar<float> _health = new SyncVar<float>();` any `T`; `_health.OnChange += (float prev, float next, bool asServer) => ...`; `SyncTypeSettings(sendRate)` with `WritePermission.ClientUnsynchronized`, `ReadPermission.ExcludeOwner`, `UpdateSettings()` — [FishNet SyncVar](https://fish-networking.gitbook.io/docs/manual/guides/synchronizing/syncvar)
- **Prediction v2 shape**:
  ```csharp
  public struct ReplicateData : IReplicateData { ... Dispose(); GetTick(); SetTick(); }
  public struct ReconcileData : IReconcileData { ... }
  [Replicate] private void RunInputs(ReplicateData data, ReplicateState state = ReplicateState.Invalid, Channel channel = Channel.Unreliable) { ... }
  [Reconcile] private void ReconcileState(ReconcileData data, Channel channel = Channel.Unreliable) { ... }
  ```
  Flow: `Update` captures one-frame inputs → `TimeManager.OnTick` builds replicate data (non-owners pass `default`) → `[Replicate]` simulates (via `PredictionRigidbody` for physics) → `OnPostTick` calls `CreateReconcile()` → `[Reconcile]` corrects; `TickNetworkBehaviour` offers overrides; *state forwarding* passes the owner's inputs through the server to other clients so they replay inputs they didn't generate; `PredictionManager.RedundancyCount` sends redundant replicates (arrive as `ReplicateState.Created` with defaults when the sender stopped) — [FishNet prediction: controlling an object](https://fish-networking.gitbook.io/docs/manual/guides/prediction/creating-code/controlling-an-object)
- Forum views: FishNet docs "brief ... almost no code examples, so they often had to read the source"; Discord support "excellent ... answered within minutes"; "even better than Mirror"; one user chose it over NGO citing "Unity's track record in networking"; another considers moving NGO→FishNet but "the switching cost is too high" — [Unity Discussions](https://discussions.unity.com/t/fishnet-vs-netcode-for-game-objects/928418); a 2026 roundup says FishNet's licence is "source-available rather than plain open source, and it restricts certain competing networking products" — [dev.to 2026 stack guide](https://dev.to/gamedevtoollab/choosing-the-right-real-time-networking-stack-for-unity-in-2026-29f4) (not verified against LICENSE.md; see Gaps)
- "FishNet is the only free solution providing built-in client-side prediction" (vendor-aligned claim) — [dev.to oceanviewgames](https://dev.to/oceanviewgames/cross-platform-multiplayer-networking-in-unity-fishnet-mirror-and-photon-compared-3m36)

#### PurrNet
- Repo: 707 stars, 84 forks, MIT; spawn with plain `Instantiate()`/`Destroy()`; RPCs: Server/Observer/Target, "static, generic, awaitable, UniTask, and coroutine forms"; *Network Modules* (reusable, nestable; SyncVar/SyncList/SyncDictionary are built on them); *Network Rules* per object for who can spawn/despawn/own/observe/call RPCs; "PurrDiction gives you rollback prediction with optional determinism"; cookie-based reconnection; "compile-time generated packers, delta compression, and a BitPacker"; transports UDP, WebSockets, Steam, UTP, Nakama, Local, PurrTransport, Composite; Unity 2022+ — [GitHub](https://github.com/PurrNet/PurrNet)
  ```csharp
  [ServerRPC] void DoSomethingOnServer() { }
  [ServerRPC] static Task<int> GetMyNumber() => Task.FromResult(42);   // awaitable static RPC
  [Serializable] public class PlayerHealthModule : NetworkModule {
      [SerializeField] int _health;
      [ServerRPC(requireOwnership: true)] public void TakeDamage(int damage) { _health -= damage; }
  }
  ```
- Docs: "100% free", no pro tier, "no revenue sharing or up-front cost"; Network Rules allow "full client authority for prototyping and move to server authority later" ("Server Auth" vs "Everyone"); no baking of components or scene IDs so prefabs can be nested and rearranged — [purrnet.dev docs](https://purrnet.dev/docs); gitbook notes "PurrNet is still in the early stages!", releases 1.25.x — [search summary of purrnet.gitbook.io](https://purrnet.gitbook.io/docs)
- User praise: "hands down the best system" for a small two-player game—simple spawn/despawn, nested networked objects, async RPCs with return values; caveat "new and underdocumented" — [Unity Discussions](https://discussions.unity.com/t/fishnet-vs-netcode-for-game-objects/928418)

#### Photon Fusion 2
- **State marking**: `[Networked] public float Health { get; set; }` (auto-property, default value allowed, "DO NOT implement these properties yourself"); `[Networked, Capacity(14)] string MyString { get; set; }`; `[Networked, Capacity(8)] NetworkArray<byte> MyArray { get; }`; ref/pointer forms `MakeRef<T>`/`MakePtr<T>`; Fusion "generates IL code that connects each property's getter and setter to the Network Object's State memory buffer"; types: blittable primitives, Unity structs, enums, `INetworkStruct`s, `NetworkString<_32>`, `TickTimer`, `PlayerRef`, `NetworkButtons`, `NetworkArray/Dictionary/LinkedList`, fixed buffers; references stored as `NetworkId`; generic `[Networked]` property of type `T` invalid; changes "typically made in `FixedUpdateNetwork()` so they work with prediction and replicate tick-accurately" — [Fusion networked properties](https://doc.photonengine.com/fusion/current/manual/data-transfer/networked-properties)
- **RPC shape**: `[Rpc(sources: RpcSources.InputAuthority, targets: RpcTargets.StateAuthority)] public void RPC_Configure(string name, Color color)`; optional trailing `RpcInfo info = default` (tick, source, channel, local-invoke flag); `[RpcTarget] PlayerRef player` parameter targets one player (`PlayerRef.None` = server); static RPCs on `NetworkRunner` take the runner as first param; `InvokeLocal` (default true), `RpcChannel.Reliable` default, `TickAligned` (default true), `HostMode = RpcHostMode.SourceIsHostPlayer`; guidance: RPCs "ideal for sharing punctual game events", late joiners "will forget it ever happened", so record effects in `[Networked]` state; "RPCs are delivered in Forward ticks and are never re-delivered in Resimulation ticks" (2.1+) — [Fusion RPC manual](https://doc.photonengine.com/fusion/current/manual/rpc); `RpcSources`/`RpcTargets` values All, Proxies, InputAuthority, StateAuthority — [Fusion rpcs](https://doc.photonengine.com/fusion/current/manual/data-transfer/rpcs)
- Input/prediction: `public override void FixedUpdateNetwork() { if (GetInput(out NetworkInputData data)) { data.direction.Normalize(); ... } }` — [Fusion 2 intro via search](https://doc.photonengine.com)
- **Topologies**: Dedicated Server (`GameMode.Server`/`Client`, "Photon does not provide servers for hosting a dedicated Fusion server application"), Client Host (`GameMode.Host`; "A rogue host can cheat"; built-in UDP NAT punch-through, relay fallback "for about 1 in 10 players"; `GameMode.AutoClientOrHost`), Single, Shared Authority (`GameMode.Shared`: each client owns what it spawns, can release/take authority; "the Photon Room manages authority changes and holds a full copy of the networked state") — [Fusion network topologies](https://doc.photonengine.com/fusion/current/manual/network-topologies)
- Pricing: free 100 CCU for one Fusion/Quantum app per studio incl. commercial use (ad-monetised counts as commercial); 20 CCU dev-only tier; paid tiers reported at $125/mo 500 CCU, $250/1,000, $500/2,000, ~$0.50/CCU above 2,000; "Plus" $95/yr adds 100 paid CCU; traffic ~3 GB per peak CCU/month — [Photon pricing docs](https://doc.photonengine.com/photon/current/pricing); [Photon blog: free 100 CCU](https://blog.photonengine.com/?p=5466); [Photon blog: pricing made simple](https://blog.photonengine.com/multiplayer-pricing-made-simple/); [third-party 2026 summary](https://crux.supercraft.host/blog/photon-fusion-pricing-2026/)
- Comparative view: Fusion "has prediction and resimulation, lag compensation, and multiple topologies, but it carries a Photon dependency and per-CCU cost" — [dev.to 2026](https://dev.to/gamedevtoollab/choosing-the-right-real-time-networking-stack-for-unity-in-2026-29f4)

#### Photon Quantum 3
- "a deterministic ECS framework for Unity multiplayer games of up to 128 players", "ideal for latency-sensitive online games" (sports, fighting, FPS); clients predict input and "roll back to re-simulate mispredictions"; "developers define only the inputs" and write no other networking code; sparse-set ECS, pointer-based C#, custom heap allocator, no C# heap allocation at runtime; DSL example `component Resources { Int32 Mana; FP Health; }` (structs, unions, enums, flags, bitsets, lists, dictionaries supported); systems are stateless `SystemMainThread` subclasses overriding `Update(Frame frame)`, iterating `frame.Filter<Transform3D, Resources>()`; a "game-agnostic authoritative server" on Photon servers synchronises clocks and distributes input every tick, extensible with a "referee" simulation; inputs/commands go in, events come out to the view; "free for development", pay beyond the free tier — [Quantum 3 intro](https://doc.photonengine.com/quantum/v3/quantum-intro)

#### Normcore (Normal VR)
- **Model**: `[RealtimeModel] public partial class ColorSyncModel { [RealtimeProperty(1, true, true)] private Color _color; }` — args are a per-model unique PropertyID, reliable/unreliable flag, and a bool that adds a C# change event; models must be `partial`, no superclass, private `_`-prefixed fields; Normcore generates the public properties "with caching, change detection, and delta compression"; components inherit `RealtimeComponent<TModel>` and override `OnRealtimeModelReplaced(previous, current)`; `isFreshModel` for initialisation — [Normcore: synchronizing custom data](https://docs.normcore.io/realtime/synchronizing-custom-data)
- **Ownership**: every model has `ownerID` (-1 = unowned, anyone may modify); an owned model (and all child models) accepts changes only from its owner; `RequestOwnership()`/`ClearOwnership()` apply immediately but the server can reject and roll back; `Realtime.Instantiate("My Player", ownedByClient: true, preventOwnershipTakeover: true, destroyWhenOwnerOrLastClientLeaves: true)`; custom components need `[RealtimeModel(createMetaModel: true)]` to carry ownership; server enforces lifetime flags even on improper disconnects — [Normcore ownership & lifetime flags](https://docs.normcore.io/room/ownership-and-lifetime-flags)
- Pricing: usage-based room hours; rooms shut down 30 s after the last client leaves; free Prototype plan with fixed allotment; Pro $49/mo with 1,000 room hours; Unlimited $49/mo + $0.01 per room hour over 1,000; Normcore Private via sales (page undated) — [Normcore pricing](https://normcore.io/pricing); [Normcore pricing docs](https://docs.normcore.io/pricing)

#### coherence.io
- `CoherenceSync` on the root of every networked GameObject makes it an Entity; the Configure window ticks public fields/properties ("Synced Variables", each with interpolation) and public methods ("Commands" = RPCs); the code-based alternative is `[Sync]` and `[Command]` attributes, both workflows combinable; *Simulate In*: Client Side (spawner owns), Server Side (only a Simulator owns), Server Side With Client Input (adds `CoherenceInput`; Simulator has State Authority, Client has Input Authority); lifetime Session Based vs Persistence (orphaned persistent entities frozen until `Adopt()`); uniqueness options; authority transfer styles Not Transferable / Steal / Request (`OnAuthorityRequested`), clients call `RequestAuthority()`; channels Default (reliable) vs Fragmented — [coherence CoherenceSync](https://docs.coherence.io/manual/components/coherence-sync)
- Baking: default Reflection Mode "very costly performance-wise" and feature-limiting; `coherence > Bake` scans indexed CoherenceSync prefabs, generates a schema file plus one C# script per prefab into `Assets/coherence/baked`; the Replication Server reads the schema; baked scripts break compilation on renames (a watchdog offers a Diagnosis window) — [coherence baking](https://docs.coherence.io/1.3/manual/baking-and-code-generation); [search summary of coherence docs](https://docs.coherence.io/coherence-sdk-for-unity/components/coherencesync)
- Pricing: credit-based ("no artificial limits for cloud resources such as CCU hours, bandwidth, DB size"); credits convert to CCU hours, simulator hours, bandwidth — [coherence credit cost & pricing](https://docs.coherence.io/support/credit-cost-and-pricing)

### Inferences
- The "mark this replicated" ergonomics cluster into: attribute-on-field needing a post-processor (Mirror, Fusion, coherence) — minimal syntax, but hidden codegen and 64-field/type limits; generic wrapper field (NGO, FishNet, PurrNet) — explicit, no magic, verbose (`new SyncVar<float>()`, `.Value`), but permissions/send-rate ride on the wrapper; and schema/model compilation (Quantum DSL, Normcore partial class, coherence bake) — best bandwidth control, worst iteration friction (rebake/recompile, rename breaks).
- Every modern Unity option that advertises prediction (FishNet, Fusion, N4E, Quantum, PurrDiction) is *tick-based with an explicit input struct*; the two libraries without that core (Mirror, NGO) are exactly the ones where prediction is "experimental"/absent and where users complain about `NetworkTransform` quality. An input-struct + fixed-tick loop appears to be the prerequisite, not an add-on.
- RPC API convergence: all libraries now put the routing in the attribute (`SendTo.X`, `RpcSources/RpcTargets`, `[ServerRPC]/[ObserversRpc]/[TargetRpc]`), require a name convention or suffix only in older designs (Mirror prefixes, NGO `Rpc` suffix), and increasingly add a trailing metadata param (`RpcParams`, `RpcInfo`, `NetworkConnectionToClient sender`). PurrNet's awaitable/generic RPCs are the one genuinely new ergonomic.
- "Shared/distributed authority" (Fusion Shared, NGO DA, coherence, Normcore, Roblox) consistently trades anti-cheat and physics consistency for latency and hosting cost, and every vendor says so explicitly; it is marketed for co-op/social, not competitive.

## Key question 2: Unreal Engine (property replication, RPCs, relevancy/dormancy, Replication Graph, Iris, Network Prediction, GAS, CMC, Mover, Chaos networked physics, serialization, Lyra, EOS)

### Takeaway
Unreal's model is unchanged in shape since UE3—`bReplicates` + `UPROPERTY(Replicated/ReplicatedUsing)` registered in `GetLifetimeReplicatedProps` with `DOREPLIFETIME*` macros and `UFUNCTION(Server|Client|NetMulticast, Reliable)` RPCs that split into `_Implementation`/`_Validate`—while the engine underneath is being swapped: Iris moved from Experimental to Beta in 5.7 (compiled in by default, still off by default, legacy and Replication Graph "remain available and supported side by side"), and Mover (the CMC successor built on the Network Prediction Plugin or Chaos networked physics) is still Experimental in 5.7. Prediction remains the sore point: CMC's saved-move pipeline is the only mature path, GAS prediction keys cover ability activation, and Chaos networked-physics resimulation is reported as unstable for vehicles across 5.5–5.8.

### Cited Findings
- **Property replication shape** (verbatim): constructor `bReplicates = true;`; `UPROPERTY(Replicated) uint32 Health;`; `virtual void GetLifetimeReplicatedProps(TArray<FLifetimeProperty>& OutLifetimeProps) const override;` with `Super::GetLifetimeReplicatedProps(OutLifetimeProps); DOREPLIFETIME(ADerivedActor, Health);`; RepNotify `UPROPERTY(ReplicatedUsing=OnRep_HealthUpdate) uint32 Health;` + `UFUNCTION() void OnRep_HealthUpdate();` (optional previous-value parameter forms); `DOREPLIFETIME_CONDITION(ADerivedActor, Health, COND_OwnerOnly);`; `DOREPLIFETIME_CONDITION_NOTIFY(..., REPNOTIFY_Always|REPNOTIFY_OnChanged)`; `DOREPLIFETIME_WITH_PARAMS` with `FDoRepLifetimeParams`; conditions `COND_None, InitialOnly, OwnerOnly, SkipOwner, SimulatedOnly, AutonomousOnly, SimulatedOrPhysics, InitialOrOwner, Custom, ReplayOrOwner, ReplayOnly, SimulatedOnlyNoReplay, SimulatedOrPhysicsNoReplay, SkipReplay, Dynamic, Never`; `COND_Custom` via `PreReplication` + `DOREPLIFETIME_ACTIVE_OVERRIDE(ADerivedActor, Health, !IsInvincible());` (per actor, not per connection, "cost more"); `_FAST` variants build descriptors at compile time; object refs need `IsSupportedForNetworking`, components can `SetNetAddressable` — [Epic: Replicate Actor Properties](https://dev.epicgames.com/documentation/en-us/unreal-engine/replicate-actor-properties-in-unreal-engine)
- **RPC shape**: `UFUNCTION(Client) void ClientRPC();` implemented as `void ClientRPC_Implementation()`; `WithValidation` adds `bool ServerUnreliableRPC_Validate(int32 RecoverHealth)`; `Reliable`/`Unreliable` specifiers, "RPCs are unreliable by default", unreliable = "not executed if the packet is dropped", "No order guarantee"; execution matrix: a Server RPC "Must be called from the client that owns this actor" (otherwise dropped); Client RPC from server runs on the owning client (or on the server if server-owned); NetMulticast from server runs on server and all relevant clients, from a client only locally — [Epic: RPCs](https://dev.epicgames.com/documentation/en-us/unreal-engine/remote-procedure-calls-in-unreal-engine)
- **Replication Graph**: replaces per-actor-per-client relevancy checks (a server CPU bottleneck) with per-client lists built from persistent shared nodes—spatial grid cells, dormancy lists for idle placed actors, always-relevant global/per-player/per-team lists, carried items updating with their owner; set via `ReplicationDriverClassName` in `DefaultEngine.ini` or `UReplicationDriver::CreateReplicationDriverDelegate()`; built for Fortnite BR: "100 connected players and about 50,000 replicated Actors"; "disabled on console builds because it doesn't currently work with splitscreen" — [Epic: Replication Graph](https://dev.epicgames.com/documentation/en-us/unreal-engine/replication-graph-in-unreal-engine)
- **Iris** (Epic docs, current page): "experimental, opt-in replication system that runs alongside" the existing one; goals: larger worlds/higher player counts (Fortnite BR 100 players cited), lower server cost, separating replication data from game-thread data for concurrency, sharing work across objects and connections; enable via plugin + `SetupIrisSupport(Target)` in Build.cs + `bUseIris = true` in Target.cs + `net.SubObjects.DefaultUseSubObjectReplicationList=1`, `net.Iris.UseIrisReplication=1`, `net.IsPushModelEnabled=1` when `net.Iris.PushModelMode=1`; concepts: Replication System (keeps "a quantized copy of all replicated state"), Replication Bridge, Net Object/Handle, Replication State/Descriptor, Protocols/fragments; "Iris expects clients to notify the replication system when state changes" (dirty tracking/push model) vs legacy polling; existing properties/RPCs "compatible with minor modifications" — [Epic: Introduction to Iris](https://dev.epicgames.com/documentation/en-us/unreal-engine/introduction-to-iris-in-unreal-engine)
- Iris status 5.7 (Epic staff, Jan 13 2026): "Iris moved from experimental to beta in 5.7. It is compiled in by default", `UE_WITH_IRIS` set to 1 and many macro uses removed, but it "remains optional ... disabled by default in 5.7 and controlled by `net.Iris.UseIrisReplication`"; "Epic has no plans to deprecate the legacy replication system or the Replication Graph. All three are planned to remain available and supported side by side" — [Epic forums: 5.7 Iris Strategy](https://forums.unrealengine.com/t/5-7-iris-strategy/2699685); third-party blogs disagree on the label (one still says Experimental in 5.7) and one claims unnamed shipped 2025–26 titles use it — [StraySpark 2026](https://www.strayspark.studio/blog/iris-replication-unreal-engine-opt-in-2026); [BorMor Iris series](https://bormor.dev/posts/iris-forest-of-ten-thousand-trees/)
- **Mover**: Epic docs: "an Unreal Engine plugin that supports modular actor movement with rollback networking using the Network Prediction Plugin or Chaos' Networked Physics system", "currently experimental", APIs/data formats "subject to change" — [Epic: Mover](https://dev.epicgames.com/documentation/en-us/unreal-engine/mover-in-unreal-engine); UE 5.7 Game Animation Sample blog: Mover "currently in Experimental", "will eventually be the successor of the Character Movement Component", new movement modes added — [Unreal tech blog 5.7](https://www.unrealengine.com/tech-blog/explore-the-updates-to-the-game-animation-sample-project-in-ue-5-7); community confusion over whether NPP is still required (thread ~640 days old) — [Epic forums: Mover 2.0 requires NPP?](https://forums.unrealengine.com/t/mover-2-0-requires-npp/2319636)
- **CMC prediction pipeline** (the model everyone copies): capture input → predict locally → send move to server → server validates/simulates → replicates result → owner reconciles, observers smooth; extending it means subclassing `UCharacterMovementComponent` (override `GetMaxSpeed`, `UpdateFromCompressedFlags`, `GetPredictionData_Client`), `FSavedMove_Character` (override `Clear`, `GetCompressedFlags`, `CanCombineWith`, `SetMoveFor`, `PrepMoveFor`) and `FNetworkPredictionData_Client_Character` (`AllocateNewMove`); anti-pattern: replicating the owner's position via RPCs on top of CMC; GAS "has explicit prediction support, and prediction keys synchronize predicted side effects", irreversible outcomes (damage, inventory, hits) stay server-authoritative; Network Prediction Plugin is "Unreal's generalized framework for bespoke, simulation-driven prediction ... a more explicit rollback/resimulation model"; pain points: rubber-banding from divergence, hidden client-only state and randomness, autonomous-proxy-vs-server rule mismatches, observer jitter, localhost testing insufficient — [Client Prediction in UE5 (firedphoenixir)](https://firedphoenixir.github.io/ClientPrediction.html)
- **Chaos networked physics**: Epic describes the *Resimulation* replication mode as "designed for server-authoritative pawns and actors" enabling client prediction for physics pawns — [Epic: Physics in Unreal Engine](https://dev.epicgames.com/documentation/unreal-engine/physics-in-unreal-engine); forum reports: in 5.5 Chaos Modular Vehicles still diverged with Physics Prediction and Capture Physics History on (resim = rewind to cached state, correct, re-sim, "visible snapping"; tune `Project Settings > Physics > Default Resimulation Replication Settings`); a tutorial author says modular vehicles across 5.5–5.8 were "completely unplayable in multiplayer" and "the client triggers resim endlessly, even when almost stationary", correction rewinds ~15 frames; Chaos Visual Debugger records physics state — [Epic forums: Apply Resimulation to Chaos Modular Vehicle](https://forums.unrealengine.com/t/apply-resimulation-to-chaos-moudular-vehicle/2694754); [Epic forums: Networked Physics Pawn Tutorial](https://forums.unrealengine.com/t/tutorial-networked-physics-pawn-tutorial/2657596?page=6)
- GASDocumentation repo (the de facto GAS reference) has ~6.0k stars, MIT — [GitHub tranek/GASDocumentation](https://github.com/tranek/GASDocumentation)

### Inferences
- Unreal's authority model is the strictest "server owns everything; clients may only call Server RPCs on actors they own" among the surveyed engines; the connection-ownership matrix (RPC dropped if the caller doesn't own the actor) is the source of most beginner confusion but also of its anti-cheat posture.
- The property pipeline is *pull-model by default* (per-actor polling for changed properties) with an opt-in push model; Iris makes dirty notification the expectation, i.e. Unreal is moving toward the explicit-dirty design (`CheckDirtyState`, `MARK_PROPERTY_DIRTY`) that NGO and Mirror users already live with.
- Because mature prediction exists only inside CMC's bespoke saved-move machinery, "predicted gameplay other than movement" in Unreal still means writing one's own rollback or adopting an Experimental plugin (NPP/Mover/Chaos resim); this is the single biggest gap a new library could target.

### Gaps
- Push model (`MARK_PROPERTY_DIRTY_FROM_NAME`, `bIsPushBased`) and `FastArraySerializer`: the Epic push-model page returned an empty body; no verified snippet.
- Dormancy settings (`DORM_*`), `NetUpdateFrequency`, `NetCullDistanceSquared`, `NetSerialize`/`FNetQuantize*` quantization and bit-writer details: not fetched (docs navigation only).
- GAS prediction key internals (what cannot be predicted, replication modes Full/Mixed/Minimal): the GASDocumentation README was not captured by the fetcher (only repo chrome).
- Lyra sample networking patterns and Epic Online Services relay/hosting: not researched (budget).
- Network Prediction Plugin's official 2026 status: Epic's Mover page still lists NPP as a backend; no explicit Epic statement on NPP's maturity found.

## Key question 3: Other engines (Roblox, GameMaker, Defold, Stride, Flax, Construct, Unigine, UEFN Verse, Core)

### Takeaway
Roblox is the standout "easy model": the engine replicates the whole data model automatically, assigns physics ownership per part (server-controllable with `SetNetworkOwner`), and exposes exactly three remote primitives (`RemoteEvent`, `UnreliableRemoteEvent`, `RemoteFunction`) whose first server-side argument is always the calling `Player`. Flax has a built-in but off-by-default high-level layer (replication + RPCs + ownership, client-server only, ~100 players); GameMaker shipped a built-in rollback system that reviewers called bare-bones; Defold, Stride and Unigine rely on third-party libraries (Photon Fusion extension, StrideNet/LiteEntitySystem, GalaxyCore); UEFN Verse exposes `@replicated` variables under a client/server/authority type system.

### Cited Findings
- **Roblox model**: the server "maintains the game's state and keeps all connected clients in sync"; replication covers "the data model, physics simulation, and chat messages"; `Workspace.StreamingEnabled` sends nearest content first; typical player latency 100–300 ms, Studio recommends simulating 50–150 ms — [Roblox: client-server](https://create.roblox.com/docs/projects/client-server)
- **Roblox network ownership**: server owns all `BasePart`s by default; anchored parts always server-owned; unanchored parts auto-assigned to clients "based on the client's hardware and how close the part is to the player's character"; server-side `part:SetNetworkOwner(player)`, `part:SetNetworkOwnershipAuto()`, `part:SetNetworkOwner(nil)` (server, "use sparingly"); the owner runs physics for that part; Roblox "can't verify physics calculations on client-owned parts" (teleport/through-wall risk), `Touched` events are tied to ownership; validate damage/hits on the server — [Roblox: network ownership](https://create.roblox.com/docs/physics/network-ownership)
- **Roblox remotes** (Luau): `remoteEvent:FireServer(a, b)` / `remoteEvent.OnServerEvent:Connect(function(player, a, b) end)`; `remoteEvent:FireClient(player, a, b)` and `FireAllClients(a, b)` / `OnClientEvent`; `remoteFunction:InvokeServer(...)` yields for `OnServerInvoke = function(player, ...) return v end`; `InvokeClient` discouraged (server errors/yields forever if the client misbehaves); argument rules: tables copied, non-string keys stringified, metatables lost, functions arrive `nil`, Instances the receiver can't see arrive `nil`; client→server traffic rate-limited with excess queued — [Roblox: remote events and callbacks](https://create.roblox.com/docs/scripting/events/remote)
- **GameMaker rollback**: requires 2022.600+ (beta at launch); setup registers the player object with `rollback_define_player`, inputs declared separately, keyboard and mouse supported; players spawn "in the top-left corner of your room" by default; TechRaptor called it "pretty bare-bones at the moment"; community reports it "doesn't work with managed objects" in the beta; third-party alternatives GGMR (predates the official feature, "allows for more customization") and an MIT lockstep demo — [GameMaker tutorial](https://gamemaker.io/en/tutorials/add-multiplayer-to-gamemaker); [TechRaptor](https://techraptor.net/gaming/news/gamemaker-multiplayer-support-added); [GGMR](https://springrollgames.itch.io/ggmr); [meseta lockstep](https://meseta.itch.io/lockstep)
- **Flax Engine** high-level networking: off by default (add `Network` tag + `Networking` dependency to the module build script, which "triggers code generation for replication and RPCs"); replicates session state, player data, scene objects (actors, scripts, SubObjects) with prioritisation; spawned objects "authoritative or weak"; RPCs with customizable `NetworkChannelType`; `NetworkManager.StartServer/StartClient/StartHost/Stop`, `ClientConnecting` validation, `ServerClientId = 0`; `INetworkObject` lifetime hooks, `INetworkSerializable` custom serialize to `NetworkStream`; swappable `INetworkDriver` backend, `NetworkLagDriver` for lag simulation; "Only client-server connections are supported", "scaling up to 100 players" — [Flax: High-level networking](https://docs.flaxengine.com/manual/networking/high-level/index.html); Flax 1.5 release notes list "objects replication over the network, RPC, concepts of object ownership, and server authority model" — [Flax 1.5 (ModDB)](https://www.moddb.com/news/flax-15-released)
- **Defold**: no built-in replication; the Photon Fusion extension offers "room-based matchmaking, efficient state replication with late join support, forecast physics prediction and flexible RPCs", plus a lower-level Photon Realtime extension — [Defold Photon Fusion extension](https://defold.com/extension-photon-fusion/)
- **Stride**: community list includes StrideNet (MIT, "workflow very similar to Unity Netcode for GameObjects or Mirror", built on Riptide, v0.1.2), LiteEntitySystem ("server-authoritative ECS with rollback and lag compensation"), ET-Stride, Regulus.Remote, and GalaxyCore ("cross-engine networking solution compatible with Unity, Stride, Xenko, and Unigine") — [Stride community networking](https://doc.stride3d.net/latest/en/community-resources/networking.html); [StrideNet on NuGet](https://www.nuget.org/packages/StrideNet)
- **UEFN Verse**: third-party guides describe Verse as running different code on client/server/authority with "the multiplayer type system is about understanding authority"; shared text uses variables "decorated with @replicated"; clients need events/custom logic to send changes to the server; an Epic forum report describes Verse-bound UMG values not replicating reliably to all clients — [UEFN Central (machine-translated)](https://uefncentral.com/tr/blog/how-does-verses-multiplayer-type-system-actually-w); [Epic forums: In-World UMG replication](https://forums.unrealengine.com/t/in-world-umg-verse-bound-field-values-do-not-reliably-replicate-to-all-clients/2739975)

### Inferences
- Roblox's ease comes from three design choices a general-purpose library could borrow: (1) *everything* in the shared tree replicates by default and the developer only opts things *out* (server-only containers), (2) physics authority is per-object and automatically assigned by proximity/hardware with a one-call server override, (3) the RPC surface is three objects, not attributes or codegen—at the cost of zero anti-cheat for client-owned physics, which Roblox documents candidly.
- Smaller engines (Flax, Stride, Defold) copy the Unity NGO/Mirror vocabulary (NetworkManager, StartHost, replication attributes, RPC attributes), suggesting that vocabulary is now the lingua franca developers expect.

- Flax `[NetworkReplicated]`/`[NetworkRpc]` verbatim attribute snippets: the sub-pages were not fetched (the index page describes but doesn't show them).
- Construct 3's multiplayer plugin, Core Games, Unigine Syncker: no results surfaced in the searches run; not covered.
- Official Epic documentation for Verse `@replicated`/`<client>`/`<server>` semantics: only third-party and forum sources found.
- Roblox adoption metrics (DAU/creator counts) were not researched; its docs don't state them.

## Key question 4: Cross-cutting — what developers call easiest, and what migration posts cite

### Takeaway
Across Unity sources there is no consensus "easiest": NGO wins on documentation/tutorials and Unity backing, Mirror on community size and a 10-year track record, PurrNet on "it just uses Instantiate/Destroy and awaitable RPCs", FishNet on built-in prediction and Discord support. Migration motives cluster around four features: built-in tick-based prediction (Mirror→FishNet), performance at CCU/with many animated objects (NGO→FishNet/Mirror), no CCU cost or vendor lock-in (Photon→FishNet/PurrNet/Mirror), and conversely "I don't want to write netcode at all" (→Fusion Shared/Quantum/Normcore/coherence, paid cloud).

### Cited Findings
- NGO vs FishNet thread: NGO "easier to pick up" thanks to tutorials and Unity backing; FishNet chosen for being "even better than Mirror", for Discord support, and because of distrust of "Unity's track record in networking"; NGO complaints centre on performance, confusing errors and inefficient `NetworkTransform`/`NetworkAnimator`; PurrNet praised for simple spawning, nested networked objects and async RPCs with return values — [Unity Discussions](https://discussions.unity.com/t/fishnet-vs-netcode-for-game-objects/928418)
- Edgegap's four-way comparison concludes Mirror is "likely the strongest and easiest starting point", calls FishNet the pick for "more demanding features" (prediction, instanced servers, LTS), PurrNet "fitting Unity's existing workflow" (Instantiate/Destroy, no baking, generic/static/awaitable RPCs), NGO beginner-friendly with "hard limitations" — [Edgegap](https://edgegap.com/blog/easiest-unity-netcode-for-game-developers)
- 2026 stack guide: Fusion = prediction/resimulation/lag comp/topologies but Photon dependency and per-CCU cost; FishNet = free, self-hosted, built-in prediction, source-available licence with competitor restrictions; NGO = Unity-native — [dev.to 2026](https://dev.to/gamedevtoollab/choosing-the-right-real-time-networking-stack-for-unity-in-2026-29f4)
- Why switch to FishNet: "go-to recommendation for developers who want community-maintained tooling that keeps pace with more demanding game types"; why stay with Mirror: "the community standard with a larger tutorial base", bandwidth irrelevant for small-scale co-op — [oceanviewgames](https://oceanviewgames.co.uk/blog/posts/cross-platform-multiplayer-networking-unity); [dev.to oceanviewgames](https://dev.to/oceanviewgames/cross-platform-multiplayer-networking-in-unity-fishnet-mirror-and-photon-compared-3m36)
- Academic measurement: RTT 46–52 ms across Fusion/FishNet/Mirror/NGO (no library had a latency edge); bandwidth Fusion < FishNet < Mirror < NGO — [ResearchGate paper](https://www.researchgate.net/publication/382960914_Comparison_of_Open-Source_Networking_Libraries_for_Unity_Engine_in_Higher_Education)
- Photon's commercial pull: a free 100-CCU commercial tier for one Fusion/Quantum app per studio — [Photon blog](https://blog.photonengine.com/?p=5466)
- Unreal side: the recurring complaint is not API shape but prediction scope—corrections/rubber-banding, owner-vs-server rule divergence, observer jitter, and the need to subclass three CMC types for even a sprint flag — [firedphoenixir](https://firedphoenixir.github.io/ClientPrediction.html); Iris adoption anxiety centres on "enabling Iris globally without measuring unsupported features, filters, bandwidth, and rollback behavior" — [StraySpark](https://www.strayspark.studio/blog/iris-replication-unreal-engine-opt-in-2026)

### Inferences
- The features repeatedly named in migration/praise posts—and therefore the ones a new library should treat as table stakes—are: (1) spawn by the engine's native instantiate/free (PurrNet, Roblox) rather than a `NetworkServer.Spawn` call; (2) typed, awaitable RPCs with return values; (3) a built-in, free, tick-based prediction/reconcile loop with an input struct (FishNet/Fusion/N4E); (4) per-object authority rules editable without code (PurrNet Network Rules, NGO DA flags, coherence transfer styles, Roblox ownership); (5) no CCU pricing or vendor relay lock-in, while still offering an optional relay (Fusion's "1 in 10 need relay" statistic shows a relay fallback is still necessary for P2P/host modes).
- Documentation quality is cited as often as features: NGO's docs are praised and FishNet's criticised even by FishNet adopters—API ergonomics alone did not decide those choices.

### Gaps
- No systematic data (survey or store ranking) on which Unity library is most used; evidence is anecdotal threads and vendor blogs.
- Specific NGO→Fusion and PUN2→Fusion migration write-ups were not found in the searches run (PUN2 not researched); Photon's own migration guides were not fetched.
- GDC talk material (Overwatch/Rocket League/Fortnite netcode) was not revisited within this budget; those talks predate the libraries above and were out of the fetch budget.
